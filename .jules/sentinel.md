## 2026-03-05 - Insecure Audit Logs Creation and Privilege Escalation Prevention in Firestore Security Rules
**Vulnerability:** The Firestore security rules for the `auditLogs` collection permitted public, client-side document creation via `allow create: if true;`, allowing malicious clients to perform log injection and fake audit records. Additionally, there was a risk of privilege escalation where regular users could alter their own `role` and `status` fields during profile updates, and potential plaintext credential storage in user documents.
**Learning:** Developers often assume that specifying `// Cloud Functions write these` means they need to allow creation in rules, or they overlook that server-side Admin SDK writes bypass rules completely, making client-side writes unnecessary. Also, omitting strict schemas on self-written collections allows clients to bypass role/status restrictions and submit plaintext sensitive fields like passwords.
**Prevention:** Restrict client-side creation on server-only collections by explicitly setting `allow create: if false;`. Always validate that immutable fields (such as role and status) are enforced during update operations by validating `resource == null || (request.resource.data.role == resource.data.role && ...)`. Enforce credential safety by rejecting fields like `password` in user documents (`!('password' in data)`).
