## 2026-03-24 - Firestore Security Rules Hardening for Credential Protection and Privilege Escalation Prevention
**Vulnerability:** Firestore rules allowed user documents to contain a `password` field in plaintext and lacked immutability constraints on critical fields during user updates, opening risks of plaintext credential leakage and user privilege escalation.
**Learning:** Standard security checks for validating user schema often overlook backend data storage properties (like prohibiting password fields in database objects). Additionally, unified `allow write` rules should be separated into specific `create` and `update` transitions to enforce that sensitive attributes like roles and status cannot be updated by the client.
**Prevention:** Always prohibit password and credential fields from being saved inside non-auth database documents using rule validators (such as `!('password' in data)`). Enforce state transition immutability on update operations by matching incoming states with existing document resources (e.g., `resource == null || (request.resource.data.role == resource.data.role && request.resource.data.status == resource.data.status)`).
