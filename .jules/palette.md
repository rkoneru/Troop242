## 2026-03-24 - Navigation Dropdowns: Hover vs. Keyboard/Touch Accessibility
**Learning:** In modern multi-device applications, navigation menus that trigger solely on hover are completely inaccessible to keyboard-only users (who rely on `Tab`, `Space`, and `Enter`) and touch/mobile users (who cannot trigger mouse hover events). Providing native `onClick` fallbacks alongside hover events is necessary to support keyboard activation and screen reader state tracking via standard ARIA attributes (`aria-expanded`, `aria-haspopup`, `aria-controls`).
**Action:** When creating hover-triggered navigation menus, always provide functional `onClick` toggle handlers on the buttons, dynamic `aria-expanded` states, and an explicit connection via `aria-controls` to the list container. Ensure `Escape` key listeners clear all open sub-navigation menus.
